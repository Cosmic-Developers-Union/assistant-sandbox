# 性能基线

状态:2026-11-26,AMD Ryzen 7 5700G(x86_64 宿主)。VM 默认 2 CPU、
4 GiB;多核正确性门禁固定覆盖 1/2/4 三档。

## 当前执行后端

- Go 侧按 2 字节边界预译码指令页,支持 RV64IM、压缩指令、AMO、
  LR/SC,以及 CPython 热路径使用的单精度浮点子集。
- x86-64 宿主使用页级 JIT。生成代码位于宿主私有映射:先以 RW
  写入,再 `mprotect` 为 RX;客体地址空间仍执行 W^X,绝不暴露
  RWX 页。
- JIT 内联最近页缓存、32 项直接映射 TLB 与 512 项软件 TLB;跨页、
  文件后端、特殊浮点值、CSR、系统调用和不支持指令回退到 C++ 批量
  解释器或 Go 单步语义基准。TLB 快路径复用页内偏移，写保护检查
  合并为单个可写位测试。
- 热点 JIT 对跨页 JAL、分支和顺序落页维护 256 项目标缓存，命中后
  直接跳到目标页入口；JALR 复用同一缓存，不再为每个动态目标返回
  C++ 页调度器。`ASSISTANT_SANDBOX_DISABLE_JIT_LINK=1` 可关闭链接
  做 A/B，默认开启。
- 批量译码页缓存为 4096 项，跨系统调用保留 Node/V8 的代码页；
  只在实际代码失效时按代际淘汰，避免每次代码写入展开全部译码页。
- 原生批量执行的内存视图按页号增量维护。新增页二分插入，Protect/
  Unmap 分别只失效区域表或页表，不再在每次 `AcquireMemoryView` 时
  收集并排序全部页。
- 页面连续进入 32 次后才编译，避免 Node/Python 启动时把一次性代码
  页展开成数百 KB 机器码。
- JIT/批量路径识别只读 cycle/time/instret 读取和单 hart fence；
  地址空间只失效实际被写保护的指令页，避免 V8 写代码页时清空
  全部翻译缓存。
- 已支持运行 linux/riscv64 Go ELF runtime；`RDTIME` 使用与
  cycle/instret 相同的单调退休指令计数。
- `ASSISTANT_SANDBOX_DISABLE_JIT=1` 可强制使用解释路径做对拍。

## 原始执行核心

`go test ./executor/cpu/riscv64 -run '^$' -bench . -benchtime=2s -count=2`

| 路径 | 吞吐 |
| --- | --- |
| x86-64 页级 JIT(热点整数/分支/访存) | 2.1–2.4 GIPS |
| 同页 JAL 热循环(3 指令，无换页) | 1.49–1.51 GIPS |
| 跨页 JAL 热循环，启用块链接 | 415–445 MIPS |
| 跨页 JALR 热循环，启用目标缓存 | 419–481 MIPS |
| 跨页 JAL/JALR，关闭块链接 | 70–76 MIPS |
| Go 单步解释 | 约 55 MIPS |

JIT 相对 Go 单步约快 38–43 倍。页级 JIT 的执行上限由宿主代码缓存、
客体指令密度和访存局部性决定;不是单纯扩大批量或缓存能继续
线性提升。

跨页微基准每轮执行 `addi`、JAL/JALR 和目标页分支三条指令，两个
代码页各进入一次；同页 JAL 基线执行同样三条指令但不换页。关闭
链接时跨页循环约 70–76 MIPS，启用后约 415–481 MIPS，块链接收益
约 5.5–6.8 倍；同页基线为 1.49–1.51 GIPS，说明换页本身仍带来约
3.1–3.6 倍开销。

- Python 1M 循环约 72–77×，仍显著高于 10×。同一代码关闭块链接时

- Node jitless 十万次循环约 55–70×。相对更早版本的 379× 的主要收益来自

- Go 10M 循环约 8–9×,已达到 10× 目标附近。

## 跨页链接后的剩余瓶颈

块链接已经把跨页热循环从约 70–76 MIPS 提升到约 415–481 MIPS，但
同样三条指令的同页循环仍有 1.49–1.51 GIPS，换页约慢 3.1–3.6 倍。
剩余成本主要来自每次换页都要：

1. 把当前页的脏寄存器写回 `JitCall.registers`；
2. 退出当前页的栈帧；
3. 在目标页重新建立栈帧，并按目标页自己的寄存器分配重新装入。

也就是说，块链接消除了 C++ 页调度，但还没有消除页边界的寄存器
保存/恢复。要跨过这部分差距，需要把多个热点页组合成 superblock
或 trace，在同一个寄存器分配域内跨块执行，并直接链接后继块。

当前证据给出的收益判断：

- 对“每次都换页”的微循环，superblock/trace 的理论上限接近同页
  三指令循环，即相对当前块链接还有约 **3.5 倍** 空间；
- 对 Python 这类控制流分散、但并非每三条指令换页的工作负载，按路线图
  的 2–4 倍作为工程预期，需用两页或三页 superblock 原型验证；
- 对 Go/Node 这类页内局部性较好的负载，收益会明显低于 Python，主要
  体现在间接跳转和跨页回边。

因此下一步不应继续扩大页缓存，而应做一个两页 superblock 原型：
统一跨页寄存器映射、消除页入口/出口、记录 JALR 目标并直接链接。

## Node/libm FP 指令覆盖

Node 的 `Math.sqrt` 负载暴露出比页边界更直接的阻塞：V8/libm 热路径大量
使用 FSGNJ、FCVT、FMV 和 fcsr CSR，而原批量译码器只覆盖部分 OP-FP。
每条未覆盖指令都会让 JIT 停止、回退 C++ 解释器或 Go 单步，再重新进入
批量执行。

已补充：

- `FSGNJ/FSGNJN/FSGNJX`
- `FCVT.S.D`、`FCVT.D.S`
- `FCVT.W/WU/L/LU.S/D`
- `FCVT.S/D.W/WU/L/LU`
- `FMV.X.W/D`、`FMV.W/D.X`、`FCLASS`
- fflags/frm/fcsr 的 CSR 读写

FMA 仍回退 Go 单步，以避免当前 libm 对精确零和异常标志的差异；它不再是
主要阻塞。本机同一 Node 22 jitless 负载：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Node 1M 次 `Math.sqrt` 循环（`console.time`） | 5.69 s | 2.00–2.13 s |
| 推算 100M 次循环 | 约 9.5 min | 约 3.3 min |

1M 次循环约提升 **2.7–2.8 倍**；相对宿主 Node 仍约 50 倍差距，说明
剩余成本主要是 V8 jitless 解释器本身和大量客体指令，而不是单一 syscall。
Python 1M 整数循环仍约 4.6 s，Python/Node 的常规回归测试保持通过。

## 10× 目标评估

页级 JIT 已消除逐指令分派、寄存器数组往返和大部分 TLB 慢查,
但不能消除客体程序本身的指令工作量。CPython 3.12 的一次整数
循环在 RISC-V 客体中约执行 1,500 条指令;即使每条只花一个宿主
周期,也高于 x86 原生 CPython 一次循环的周期数。Python 要达到
10×,下一步必须做更高层的热点识别与优化(例如 CPython 字节码
级加速、跨基本块超级块/轨迹、常量传播和冗余装入消除),而不是
继续扩大页缓存或批量。

当前结论必须按工作负载陈述:Go 计算热点已达到约 8×;C 接近
10×;Python 单线程解释循环和 Node 启动仍未达到 10×。Node jitless
从约 379× 降到约 55–70×，Python 从约 122× 降到约 72–77×。

3× 目标的指令级可行性、标准 Node 对比与可选后端决策见
[加速路线](acceleration-roadmap.md)。
